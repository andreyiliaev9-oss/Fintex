# Обновление облака для синхронизации исправлений

Клиент v74 работает и со старым облаком, но сервер v6 не умеет менять/удалять записи. До обновления правки остаются на устройстве; интерфейс не выдаёт их за сохранённые в облаке.

1. В Fintex сохраните резервную копию. Не удаляйте данные браузера.
2. Откройте **существующий** проект Google Apps Script, который обслуживает текущий `/exec`.
3. Замените код проекта содержимым `downloads/Fintex-Code.gs` (или соответствующими `backend/Auth.gs` + `backend/Code.gs`; это два варианта одного кода, не добавляйте оба одновременно).
4. Сохраните существующие свойства проекта и указатель `FINTEX_SS_ID` на согласованную новую базу. **Не запускайте создание базы заново. Исходная база `1X-hFpWRGUomCIlmQsDvV4I2m5Ke9A9FIQ4we5aypvps` не является целью обновления.**
5. Apps Script: **Развернуть → Управление развёртываниями → карандаш → Новая версия → Развернуть**. Обновляйте существующее развёртывание, чтобы `/exec` не изменился. Никакие токены/пароли не надо отправлять в чат.
6. Откройте Fintex через ту же Telegram-учётную запись, затем **Настройки → Сохранение операций → Проверить синхронизацию**. При первом подключении несовпадающие остатки/старые локальные исправления требуют явного выбора. Они не перезаписываются автоматически.
7. На двух устройствах проверьте небольшую тестовую операцию: создать → дождаться облака → исправить → проверить второе устройство → удалить → проверить второе. «Отменить» создаёт обратную ревизию, а не откатывает весь журнал.

Новый лист `LedgerEvents` создаётся лениво при первой подтверждённой мутации, в той же согласованной базе. Старые строки Transactions не переписываются. После начала работы ревизий старые клиенты получают `UPGRADE_REQUIRED` при попытке старой записи: они не могут подменить новый баланс. Обновите страницу Fintex на всех устройствах.

В этой среде нет авторизованного доступа к Apps Script: код и тесты подготовлены, но серверный деплой не выполнен. Публикация сайта на GitHub Pages сама по себе не обновляет Google Apps Script.

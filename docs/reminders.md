# FINTEX · Напоминания в Telegram (v45 / сервер v7)

Вместо двух локальных переключателей в **Настройки → Уведомления** подключена серверная система напоминаний существующего Telegram-бота. Mini App может быть закрыт: сообщения отправляет часовой триггер Google Apps Script, не браузер. Отдельный сервер, платная подписка, OS-оверлей и пароли не нужны.

**Важно:** код подготовлен и проверен локально, но Google-аккаунт владельца из репозитория недоступен. Публикация сайта не обновляет Apps Script и не создаёт триггер. Пока владелец не выполнит шаги ниже, реальная отправка не включена. Проверки Telegram Bot API и Apps Script выполнены на эмуляторе/моках, не на боевом боте.

## Однократное включение владельцем — в том числе с телефона

1. Откройте **существующий** проект Google Apps Script, к которому относится текущий `/exec`. В браузере телефона может потребоваться «Версия для ПК».
2. Скопируйте весь готовый [`downloads/Fintex-Code.txt`](../downloads/Fintex-Code.txt) в `Code.gs`, заменив прежнее содержимое. Это **единый** файл: не оставляйте в проекте дубли функций из отдельных `Auth.gs`, `Reminders.gs`, `ReminderModel.gs`. Сохраните код.
3. **Существующие свойства не меняйте:** `FINTEX_BOT_TOKEN`, `FINTEX_AUTH_SECRET`, `FINTEX_SS_ID`. Токен бота не нужно присылать в чат, вставлять в сайт или публиковать. Если облако v6 уже настроено, используются те же значения. Не запускайте создание новой базы и не подменяйте ID таблицы.
4. В списке функций выберите **`setupFintexReminders` → Выполнить**, разрешите Google доступ к существующей таблице, внешним запросам и триггерам. Функция проверит бота через `getMe`, создаст лист `Reminders` в **настроенной** базе и один триггер каждые 15 минут. Повторный запуск безопасен: лишние триггеры этой функции удаляются, чужие не затрагиваются. Тестовых сообщений пользователям эта функция не рассылает.
5. **Развернуть → Управление развёртываниями → карандаш → Новая версия → Развернуть**. Обновите текущее развёртывание, сохранив прежний `/exec` URL и существующие параметры доступа/исполнения от имени владельца. Если Google запросит дополнительную авторизацию, подтвердите её в своём аккаунте.
6. Откройте FINTEX заново **в Telegram**, зайдите в **Настройки → Уведомления → Проверить подключение**. Должно появиться «Серверное расписание подключено». Включите нужные типы, проверьте часовой пояс и время, нажмите **«Сохранить на сервере»** и согласитесь на сообщения Telegram. Если требуется — нажмите «Открыть бота», запустите/разблокируйте его и повторите включение. При отказе настройки на сервере не включаются.

Не создавайте новый Telegram-бот, приложение или таблицу. Единственный дополнительный лист `Reminders` создаётся автоматически, без изменения финансовых строк и схемы существующих листов. Исходная старая таблица не затрагивается, если `FINTEX_SS_ID` по-прежнему указывает на согласованную новую базу.

### Проверка реальной доставки

- Для первой проверки выберите только «Проверить учёт операций», если за местное сегодня нет расходов, и время в ближайшие разрешённые 15–30 минут. Часовой пояс должен соответствовать вашему местному времени. Дождитесь очередного запуска (Google может задержать его).
- Если расходы сегодня уже есть, проверка учёта **намеренно пропускается**. Альтернатива — выбрать ежедневный итог и ближайшее дневное время итога.
- После отправки нажмите «Проверить подключение»: «Принято Telegram» означает успешный ответ API, **не прочтение пользователем**. Откройте приложение по кнопке сообщения.
- Максимум одна попытка за день/20 часов: повторные ручные запуски не должны присылать дубликаты. Не удаляйте журнал доставки ради повторного теста на реальных пользователях.
- Верните комфортное расписание после проверки. В Apps Script → «Выполнения» проверьте отсутствие ошибок/превышений квот. Не публикуйте логи с секретами.

## Доступные напоминания

| Тип | Условия |
| --- | --- |
| 🧾 Чеки | Нет подтверждённого нового чека ≥3 дней; при отсутствии истории — ≥3 дней с включения. Это не утверждение о совершённых покупках. |
| 💳 Учёт операций | В доступных локальных/облачных данных нет расхода за текущий местный день. Формулировка — «проверьте, все ли добавлено», а не «у вас есть пропущенные операции». Наличие хотя бы одного расхода подавляет эту общую подсказку, но не доказывает полноту учёта. |
| 📅 Платежи | В последнем снимке есть неоплаченный платёж со сроком сегодня или в ближайшие 2 дня. Одна попытка на сочетание ID и даты платежа. Отправляется только общий текст с датой, без названия/суммы. |
| 📊 Итоги | Ежедневно либо по воскресеньям, в отдельное выбранное время. По умолчанию — приглашение посмотреть аналитику без сумм. Отдельная галочка разрешает суммы **только облачного журнала** за день или текущую неделю понедельник–воскресенье на момент отправки. Остаток не выдаётся за накопления. |
| 🎯 Цели | По средам при наличии незавершённой цели из свежего снимка. Не утверждает, что пользователь забыл/не смог накопить. |

Все сообщения содержат кнопку **«Открыть FINTEX →»** на существующий Mini App. Вычисления не выдумывают покупки, недостающие операции, причины решений или сумму накопленного вне облачного журнала. Доходы/расходы в числовом отчёте исключают явно отмеченные переводы/возвраты/снятие, но не восстанавливают природу неправильно размеченных операций.

## Частота, время и ограничения

- Отправка только при `enabled: true`, по умолчанию **выключена**. Локальная галочка сама по себе ничего не активирует: требуется загрузка действующих настроек, явное сохранение с подписанным Telegram initData и согласие на сообщения через `requestWriteAccess` (Telegram API ≥6.9).
- `requestWriteAccess` открывается только по действию пользователя. Его callback не считается серверным доказательством Telegram-разрешения: сервер фиксирует **явный аутентифицированный opt-in самого владельца UID**, а Telegram дополнительно проверяет реальную возможность отправки. На чужой `chat_id` подписаться нельзя; клиент вообще не задаёт адресата.
- Время выбирается с **09:00 до 21:59**, в поддерживаемом часовом поясе IANA. Автоопределённый неподдерживаемый пояс заменяется на UTC — перед сохранением проверьте его. Часовой пояс скрипта не подменяет пользовательский; переходы на летнее время учитывает `Utilities.formatDate`.
- Проверка расписания каждые 15 минут, точная доставка в выбранную минуту не гарантируется. Допустимо окно 90 минут после времени, но никогда после 22:00. Ночные пропуски не догоняются.
- Максимум **одна попытка за местный день** и интервал ≥20 часов, включая смену пояса/настроек. Ошибка или неопределённый результат не вызывают слепой повтор в тот же день.
- При совпадении сначала итог, затем ближайший платёж, затем остальные подходящие типы по давности отправки. Чеки/учёт/цели не повторяются чаще чем раз в 3 дня. **При ежедневном отчёте остальные типы могут не отправляться** из-за общего лимита; для сочетания напоминаний удобнее недельный итог.
- Чеки/платежи/цели и общая проверка прекращаются после 7 дней без обновления снимка активности; запланированные отчёты остаются. Неизвестные операции не «обнаруживаются» в закрытом Mini App. Облачные новые расходы дополнительно подавляют устаревшую проверку учёта.
- Паузы Google, квоты Apps Script, сеть или остановленный триггер могут приводить к пропуску. Это не гарантированный канал важных платежей. Не полагайтесь на него как на единственный способ не пропустить срок.

## Какие данные хранятся

Отдельный лист `Reminders`:

- `user_id` — проверенный ID личной Telegram-учётной записи;
- `settings_json` — типы, время, пояс, включение, согласие на числовые отчёты;
- `context_json` — дата последней активности/обновления, последнего подтверждения чека и расхода, до 50 идентификаторов/сроков неоплаченных платежей, флаг незавершённой цели;
- `delivery_json` — время/день последней попытки, дату/версию явного согласия, ограниченные ключи событий (до 80), последние попытки по типам, безопасный статус и пауза Telegram;
- `updated_at` — время обновления строки.

Изображения, OCR-текст, названия покупок/платежей и суммы подушки для этой функции не передаются. Суммы необязательного отчёта берутся из уже существующего облачного журнала, не из нового фонового банковского доступа. Приватные суммы в боте могут быть видны на экране блокировки — галочка выключена по умолчанию. Режим приватности Mini App не отзывает ранее включённые числовые отчёты: выключайте их отдельно.

Новые подтверждения чеков получают локальный `confirmed_at`, независимо от даты покупки. Банковский скриншот не считается чеком. По старым записям без этой метки время загрузки не выдумывается. Дата последнего чека/расхода объединяется с более поздней известной датой, чтобы старое устройство не стирало новую активность. Список платежей/флаг цели — последний синхронизированный снимок; изменения на закрытом/несинхронизированном устройстве серверу неизвестны.

Устаревшие данные или ошибки обновления снимка могут повлиять на выбор подсказки. Контекст обновляется после финансовых изменений с задержкой 3 секунды и при возврате в приложение; неизменившийся снимок ограничен частотой 5 минут. Закрытие приложения до завершения запроса может оставить старый снимок. Фоновый ответ не перезаписывает несохранённые настройки формы.

## Безопасность и остановка

`reminders_get`, `reminders_save`, `reminders_context` — только POST с проверенным, не просроченным Telegram initData через существующий `authTelegram`. UID адресата берётся из подписи; переданный несовпадающий `user_id` отклоняется. Старые ingest-токены, GET, UID без подписи и гостевой браузер не могут включать отправку или читать настройки. Настройки не меняют баланс/операции.

Состояние попытки фиксируется **до** обращения к `sendMessage` под серверной блокировкой. Это компромисс в пользу отсутствия дублей: при тайм-ауте возможен пропуск, не гарантируется exactly-once доставка. Текст отправляется без HTML/Markdown parse mode. Токен остаётся в Script Properties; URL Bot API, исключения с токеном и содержимое запросов не пишутся в лог.

- `403` или известный `400 chat not found / user is deactivated` останавливает подписку и удаляет снимок. Включение снова — только явное действие пользователя после восстановления доступа.
- `429` сохраняет `retry_after` (1 минута–24 часа), дневной лимит при этом не отменяется.
- Сетевой/неопределённый результат отражается безопасным статусом. «Принято Telegram» не равно прочитано.
- **Пользователь:** выключить главный переключатель → «Сохранить на сервере». Контекст удаляется, настройки/минимальный журнал доставки остаются для подавления дублей. Уже принятые Telegram сообщения не отзываются. При недоступном Mini App можно заблокировать бота в Telegram.
- **Владелец:** вручную выполнить `stopFintexReminders` — удалит только триггеры `sendFintexReminders`, не чужие триггеры, финансовые данные или предпочтения пользователей.

Отправитель рассчитан на небольшой проект Apps Script: до 20 пользователей за запуск, до 4 минут работы, циклический курсор для дальнейших строк. Установщик не отменяет квоты Google. При росте аудитории потребуется пересмотр ёмкости/очереди; некоторые окна могут пропускаться. Никаких платных сервисов автоматически не подключается.

## Разработка и проверки

- `backend/ReminderModel.gs` — чистые правила, валидация и выбор одной подсказки;
- `backend/Reminders.gs` — изолированный лист, API, установка/остановка расписания, Bot API, статусы;
- `reminders.js` — интерфейс, разрешение Telegram, серверные настройки, минимальный снимок;
- `scanner.js` — только дата нового подтверждения чека;
- `scripts/bundle-backend.cjs` — воспроизводимый единый установщик `.gs`/`.txt`, входит в `npm run build`.

Проверено: **88 модульных тестов, 93 браузерных теста, сборка PASS**. Новые проверки покрывают согласие/отказ, чужой UID, серверный opt-out, дубли и тайм-ауты, 403/429, UTC/местные сутки/DST, ротацию/лимиты, квоты очереди, фильтрацию контекста, отсутствие финансовых изменений, старый сервер, фоновые черновики и 320px во всех палитрах/режимах. Превью `docs/reminders-preview.png` сделано с тестовым сервером.

Реальная доставка существующим ботом, разрешения Google и триггер в аккаунте владельца **не проверены и не включены** в этой среде. Выполните шаги установки и один живой тест перед использованием.

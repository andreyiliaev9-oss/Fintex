# Fintex: проверка сохранности и исследование удобства

**Статус:** автоматизированный стенд проверен; испытания на физических устройствах и с новыми пользователями НЕ ПРОВЕДЕНЫ. Наблюдений участников и измерений реального GAS пока нет. Этот комплект не повышает продуктовую оценку сам по себе.

## 1. Что уже проверяет стенд

`tests/multidevice-recovery.spec.cjs` использует независимые браузерные контексты с раздельными хранилищами, настоящий `cloud.js`, подписанные тестовые Telegram-запросы и код `backend/Code.gs` / `backend/Auth.gs`. `FintexCloud.request` не подменяется. Перехват транспортного запроса передаёт тело в серверный код без изменения. Google Sheets, блокировки, Telegram и транспорт эмулируются в памяти. Никакой связи с личной базой или действующим GAS нет.

| ID | Сценарий | Проверяемый результат |
|---|---|---|
| A1 | Покупка без сети → закрытие контекста → восстановление сохранённого localStorage → второй клиент | Та же операция и ID мутации; один расход; оба клиента и стенд сходятся |
| A2 | Явно подготовленный офлайн-режим → браузер без сети → покупка → перезагрузка → возврат сети | Запись переживает реальную офлайн-перезагрузку страницы; после соединения отправляется один раз |
| A3 | Сервер записал покупку, но ответы потеряны → перезапуск клиента | Повторяет прежний ID мутации, баланс не списывается дважды |
| A4 | Один клиент удаляет без сети, другой правит → перезапуск | Удаление не теряется молча; конфликт сохраняется; явный выбор удаления создаёт tombstone |
| A5 | Одновременные офлайн-правки → перезапуск | Локальная версия остаётся до явного выбора облачной; затем остатки сходятся |
| A6 | Настоящий скачанный файл → новый профиль → восстановление | ID и остаток восстановлены, облако на паузе, другой клиент и сервер не меняются |
| A7 | Задержанный ответ начат до восстановления | Не отменяет восстановление и облачную паузу |
| A8 | Восстановление старой копии → отдельное согласие той же учётной записи | Разные версии показаны как конфликт, замена только явным выбором |

«Перезапуск контекста» в A1/A3/A4/A5 означает новый browser context с восстановленным Playwright storageState, не аварийное завершение ОС или физического телефона. A2 использует настоящий service worker, browser offline и reload. Стенд не воспроизводит квоты/задержки/конкурентность Google Sheets, доставку Telegram и ограничения Safari.

### Повторить

```sh
npm ci
npx playwright install chromium
npm run build
npm test
npm run test:reliability
```

При готовом браузере задайте `CHROMIUM_EXECUTABLE_PATH`; в текущем Arena sandbox также нужен `LD_LIBRARY_PATH=/tmp/al2023/lib`. Отчёты Playwright и обезличенный журнал транспортных действий находятся в игнорируемом `test-results/`. Журнал не включает initData, ключи или личные данные. Результаты конкретного прогона — в [evidence.md](evidence.md).

## 2. Что необходимо для реальной проверки сохранности

Нужен владелец **двух физических устройств**, отдельной тестовой учётной записи Telegram, тестового бота и **отдельной пустой таблицы**. Доступы, initData и секреты нельзя присылать в чат, записывать в отчёт или включать в скриншоты. Настройку сервера выполнять по документации `backend/`; не копировать боевую таблицу и не менять её endpoint.

Перед началом записать: версию/коммит клиента; версию реально развёрнутого GAS; дату; модели устройств и ОС; браузер/Telegram; одинаковость тестовой учётной записи. Если протокол исправлений не поддерживается, зафиксировать BLOCKED, а не считать тест пройденным. **Пока эти ресурсы и оператор не предоставлены, этап заблокирован, не выполнен.**

### Полевой прогон R1–R8

Обозначения: A/B — два устройства, начальный тестовый остаток **1 000 ₽**, целей и платежей нет. Инициализировать остаток на стенде штатной явной сверкой; после подключения обоих устройств убедиться, что они одинаковы. Не редактировать таблицу во время сценариев.

1. **R1, создание:** A записывает расход 100,25 ₽. На A/B и в тестовом облаке одна запись с одинаковым ID, остаток **899,75 ₽**. Повторная проверка ничего не меняет.
2. **R2, потеря сети:** отключить сеть на A. A меняет сумму R1 на 150,50 ₽; остаток A **849,50 ₽**, B пока **899,75 ₽**. Закрыть и заново открыть подготовленное офлайн-приложение. Вернуть сеть, явно проверить. Итог A/B **849,50 ₽**, прежний ID, без дубля.
3. **R3, конфликт:** отключить сеть на A/B. A меняет сумму на 200 ₽, B — на 250 ₽. Включить A и проверить, затем B. До выбора B сохраняет свою версию и показывает обе. Выбрать облачную на B; итог A/B **800 ₽**, сумма операции 200 ₽.
4. **R4, удаление:** A удаляет эту запись, проверяет облако. B после проверки тоже не содержит её; A/B **1 000 ₽**. Перезапуск и повторная проверка не возвращают запись.
5. **R5, удаление против правки:** создать новую покупку 100 ₽, синхронизировать A/B. Без сети A удаляет её, B меняет на 250 ₽. Сначала отправить B, затем A. На A должен быть конфликт, не тихое возвращение записи. Явно отправить локальную удалённую версию; итог A/B **1 000 ₽**, запись отсутствует.
6. **R6, файл:** A записывает 100,25 ₽, проверяет облако и скачивает копию. Открыть файл из «Файлов»/загрузок, проверить через независимую проверку копии. Затем A меняет сумму на 200 ₽, синхронизирует B: **800 ₽**. На отдельном **пустом тестовом профиле браузера** восстановить прежний файл: **899,75 ₽**, старый ID, облако на паузе; A/B остаются **800 ₽**. Не очищать рабочий профиль ради этого шага.
7. **R7, возврат к облаку:** на восстановленном профиле отдельно разрешить ту же тестовую учётную запись. Различия должны потребовать сравнения; принять облачную версию. Итог всех тестовых клиентов **800 ₽**, одна операция 200 ₽.
8. **R8, закрытие:** на обоих устройствах закрыть/открыть приложение и повторно проверить синхронизацию. Сверить ID, суммы, количество, остаток и видимые статусы; скачать финальную копию и проверить файл. Не делать вывод по одному остатку: пропавшие и дублирующиеся операции могут компенсироваться.

Для каждого R: PASS / FAIL / BLOCKED / NOT RUN, ожидание и факт, время, версии устройств, обезличенное доказательство. FAIL при любом молчаливом исчезновении, дубле, изменении остатка без действия, загрузке копии без согласия или ложном статусе «В облаке». При FAIL остановиться, сохранить файлы/ID и отдельные снимки каждого клиента; не чистить хранилище, не повторять импорт наугад. Не имитировать потерю ответа на боевом сервере: A3 проверяется автоматически, для реального аналога нужен управляемый тестовый прокси.

## 3. Исследование с 5–7 новыми пользователями

### Набор и безопасность

- Участники раньше не пользовались Fintex. Желательно 2–3 iPhone, 2–3 Android и один человек, который редко ведёт финансовый учёт; группы могут пересекаться.
- Приглашение: «Проверяем понятность приложения личного учёта, не ваши финансовые навыки. Около 25–35 минут. Только вымышленные данные. Участие добровольное, можно закончить в любой момент». Согласие на запись экрана получать отдельно; по умолчанию видео/аудио **не записывать**.
- Только отдельный пустой профиль/тестовое устройство. Никаких личных чеков, банковских уведомлений, имён, телефонов, логинов и паролей в заметках. Участники обозначаются P01–P07. Перед передачей устройства отключить личные уведомления.
- Не подключать пользовательскую тестовую сессию к облаку. Копия имеет `cloudOwner:null`; облачную паузу после импорта не снимать. Проверка сохранности с двумя устройствами — отдельный этап.

### Единые исходные данные

Наблюдатель заранее импортирует [synthetic-backup.json](synthetic-backup.json) **только в пустой профиль**. Копия содержит вымышленные рублёвые записи, не содержит доступов и не импортируется автоматически. Даты приложенного примера привязаны к 24.11.2026. Перед исследованием пересоздать файл на день сессии:

```sh
node scripts/create-study-backup.cjs --date YYYY-MM-DD --output .cache/study-backup.json
```

Команда не трогает приложение, сеть или браузерное хранилище. Наблюдатель импортирует файл вручную. На нового участника — отдельный пустой профиль с тем же исходным файлом. Проверить исходный остаток **8 750,25 ₽**, 4 операции, цели **1 250 ₽**, один предстоящий платёж **750 ₽**, зарплата через 10 дней. Готовить данные и закрыть предупреждения настройки ДО запуска таймера. Финансовые подсказки не объяснять заранее.

### Как вести сессию

1. Дать [отдельный лист заданий](participant-tasks.md), без этого протокола и критериев правильности. Сказать: «Мы проверяем интерфейс, не вас. Говорите, что ищете и чего ожидаете».
2. Открыть [recorder.html](recorder.html) наблюдателю на другом экране. В нём нет связи с приложением, сбора финансов или отправки в сеть; заметки хранятся в памяти до ручного экспорта. Не использовать как анкету, заполняемую участником на тестируемом телефоне.
3. Читать задания дословно. Старт времени — после прочтения; стоп — при выполнении или отказе. Через 3 минуты предложить закончить задачу и записать незавершённость. Это ориентир для наблюдателя, не принудительный таймер.
4. При вопросе «куда нажать?» ответить «Где вы ожидали бы это найти?». Если затем требуется конкретная навигационная подсказка, записать её и отметить ASSISTED; успех после подсказки не считать самостоятельным. Не перехватывать устройство молча.
5. После каждого задания: «Насколько легко было выполнить? 1 — очень трудно, 7 — очень легко». Отдельно записывать наблюдаемое поведение и слова участника, не свои объяснения его мотивации.
6. В конце: «Что было самым непонятным?», «Как вы понимаете, где сейчас хранятся записи?», «Чего не хватает, чтобы доверять приложению?». Выгрузить обезличенный протокол. Проверить файл; не публиковать заметки в Git. Удалить сырые материалы после согласованного срока (по умолчанию 30 дней).

### Критерии наблюдателю — НЕ показывать участнику

| Задача | Успех без подсказок | Критический сигнал |
|---|---|---|
| T1, покупка | Одна новая запись «Учебный чай», 125,50 ₽, сегодня; итог 8 624,75 ₽ | Дубль, неверный знак или сумма, участник считает незаписанный ввод сохранённым |
| T2, поиск | Находит исходную «Учебную кофейню», 249,75 ₽, вчера; ничего не меняет | Редактирует/удаляет, пытаясь просто найти |
| T3, понимание денег | Объясняет: общий остаток 8 624,75 ₽ включает отложенное; «можно потратить» 6 624,75 ₽ = остаток − цели 1 250 − платёж 750; дневной ориентир — не банковский остаток | Считает ориентир банковским остатком или полагает, что цели уже вычтены из общего остатка |
| T4, ближайший платёж | Находит «Учебный интернет», 750 ₽, дата сессии +4 дня, не оплачивает | Случайно отмечает оплату или не отличает будущий платёж от факта расхода |
| T5, копия | Скачивает реальный JSON-файл, находит его в файловом менеджере и запускает независимую проверку; понимает, что проверка не восстанавливает | Считает сам клик доказательством сохранённого файла или ожидает замену данных при проверке |

Если T1 не выполнена, наблюдатель после записи неуспеха нормализует тестовый профиль до одной покупки 125,50 ₽, отмечает это вмешательство, затем запускает T2. Между T2–T5 новые операции не создавать. Для T3 принимать эквивалентные объяснения словами, а не требовать точного текста; главный критерий — отсутствие опасной путаницы.

### Итог и решения

- Отчёт: число реально завершённых сессий и устройств; самостоятельные успехи по каждой задаче **x/n**; assisted отдельно; медиана времени только успешных самостоятельных попыток; медиана SEQ; перечень проблем с наблюдаемыми примерами и числом затронутых участников.
- При 5–7 участниках не делать статистических заявлений обо всех пользователях, не объявлять «UX 10/10» и не выводить общий балл автоматически из SEQ.
- Ориентиры следующей итерации: нет потерь/дублей; минимум 5 из 6 (либо 4 из 5 / 6 из 7) самостоятельно завершают T1/T2; **любая** опасная трактовка T3 или T5 требует разбора; повтор одной проблемы у двух участников — приоритет P1. Это критерии решений, не уже достигнутые результаты.
- P0: потеря данных/неожиданная запись/раскрытие личных сведений — остановить сессию и исправить до продолжения. P1: блокировка основной задачи или неверное понимание денег. P2: лишние действия, непонятная подпись, неудобство без финансовой ошибки.

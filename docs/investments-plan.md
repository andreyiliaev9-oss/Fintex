# Fintex · Учебные инвестиции

Дата проверки источников: **24 ноября 2026**.

## Актуальное решение: только бесплатно

Пользователь выбрал **никаких платных подписок на котировки, в том числе в дальнейшем**. Коммерческие тарифы ниже оставлены как архив исследования, не как предложение к подключению. Автоматический переход на оплату, paid fallback, ввод ключей брокера и реальные сделки исключены.

**Реализована бесплатная учебная основа v26:** отдельный локальный виртуальный остаток 100 000 ₽, 5 уроков с проверкой ответа и сохранением прогресса, дневник решений и явный сброс только учебных данных с подтверждением. Вход — из аналитики и настроек. Основной баланс, транзакции и `calcMetrics()` не менялись.

**Не реализованы:** каталог акций, котировки, графики, исполнение сделок и учёт позиций. Пока нет проверенного бесплатного источника с правами на публичный показ, покупка и продажа отключены. Пустой портфель не содержит вымышленных сделок или случайных цен. Нельзя обещать бесплатные realtime-котировки всех бирж.

Данные хранятся только в `fp_invest_learning_v1` в localStorage; это не защищённый брокерский счёт и не облачное сохранение. Очистка браузера может удалить обучение. Ошибка чтения не перезаписывает исходную запись; ошибка сохранения видна пользователю и не выдаётся за успех. Текст дневника экранируется.

Подключение рыночного источника в будущем допустимо только при **нулевой стоимости для выбранного публичного использования** и подтверждении прав/лимитов/покрытия. При смене условий источник отключается, а не становится платным. Секреты бесплатного API, если они потребуются, всё равно нельзя хранить в браузере; понадобится отдельно доступная бесплатная серверная инфраструктура с контролем квот. Она сейчас не развёрнута.

## 1. Архив исследования источников

Первоначально изучались коммерческие кандидаты Twelve Data Business, Finnhub Enterprise, Alpha Vantage и MOEX ISS. Этот выбор **не принят**, платные источники не подключаются. Платные подписки не оформлялись, ключи не запрашивались, живое API-подключение не тестировалось.

Дальнейшие разделы 2–8 описывают результаты исследования и целевую архитектуру возможного расширения. Они не означают, что backend, котировки или торговый ledger уже существуют. Для реализации v26 backend не требуется.

## 4. Архитектура

Текущий Fintex — статическое приложение, которое может размещаться на GitHub Pages. Для новой функции предлагается отдельный backend/serverless API и база данных; действующий хостинг и backend в этом этапе не развёрнуты.

```text
Fintex UI
  └─ /api/investments/* (relative URLs)
      ├─ проверка сессии / Telegram initData на сервере
      ├─ ограничения частоты запросов и журнал операций
      ├─ реестр инструментов и разрешений по биржам
      ├─ адаптер поставщика → кэш / подписки на активные инструменты
      └─ учебный ledger / заявки / портфель → транзакционная БД
```

- Production: reverse proxy или serverless routes должны обслуживать `/api/investments/*`. GitHub Pages самостоятельно такие API не исполняет. Не зашивать `localhost` в браузерный код.
- Секретный ключ поставщика — только в секретах серверного окружения. Не хранить в Git, HTML, браузере или сообщениях. Логи должны маскировать ключ и заголовки доступа.
- Никакого универсального открытого прокси к поставщику: только разрешённые эндпоинты/параметры, аутентификация, лимиты, разрешения на инструменты и общая серверная квота.
- Для Telegram сервер проверяет подпись и свежесть `initData`, затем выпускает сессию. Не доверять `initDataUnsafe` и присланному клиентом user id. Для обычного браузера нужен отдельный вход либо только явно локальное учебное сохранение без выдачи его за защищённый счёт.
- Рыночные данные и состояние счёта авторитетны на сервере. Клиент не присылает цену исполнения, комиссию или готовый баланс.
- Поставщик заменяем через адаптер. Недоступный рынок не заменяем похожим тикером или синтетической ценой.

### Предлагаемые серверные ресурсы

- `GET /api/investments/capabilities` — разрешённые рынки, уровни данных, ограничения и атрибуция.
- `GET /api/investments/instruments?query=...&cursor=...` — поиск и пагинация только по известному каталогу, с доступностью цен отдельно.
- `GET /api/investments/quotes?ids=...` — пакет котировок с лимитом размера запроса.
- `GET /api/investments/candles?instrumentId=...&interval=...` — исторические данные в разрешённых диапазонах.
- `GET /api/investments/account` — виртуальные остатки, позиции, версия счёта.
- `POST /api/investments/orders` — инструмент, сторона, количество, одноразовый quote token, версия счёта, `Idempotency-Key` и необязательная запись дневника.
- `GET /api/investments/orders` — история и статусы демосделок.
- `POST /api/investments/reset` — явное подтверждение; новый идентификатор поколения счёта, чтобы старые запросы не изменили новый счёт.

Это предлагаемый контракт, не существующие маршруты.

## 5. Контракт данных и честные котировки

У инструмента: стабильный внутренний id, provider id, symbol, биржа/MIC, валюта котирования, единица цены, часовой пояс, lot size, price tick, quantity step, статус листинга и доступность данных. Один тикер без биржи не уникален. Метаданные, необходимые для корректного расчёта, должны быть получены от источника, а не угаданы.

У котировки:

```text
instrumentId, price, optional bid/ask, currency,
provider, feed, exchange,
asOf (время рыночного события), receivedAt (время приёма сервером),
dataMode: realtime | delayed | eod,
delaySeconds, marketState: open | closed | halted | unknown,
marketStatusAsOf, stale, tradableInDemo, unavailableReason
```

- Цены и суммы в API — десятичные строки, расчёты с явной точностью валюты и инструмента. Не использовать обычный float для ledger.
- Realtime, delayed и EOD — уровни происхождения данных. Stale — отдельное состояние; новый HTTP-ответ не делает старую цену новой.
- Проверять торговую сессию, праздники, смену времени и остановки торгов по источнику. «Биржа открыта» не следует выводить только из локального времени пользователя.
- Для delayed оценивать свежесть относительно заявленной задержки, но в первой версии не исполнять по нему сделки «прямо сейчас». Для будущего replay показывать отдельное историческое время и не открывать будущие свечи.
- При отсутствии цены показывать «Данные недоступны», не `0`, не случайное число и не старую цену с бейджем Live.
- В смешанном портфеле не суммировать USD/EUR/RUB без явного курса с источником и временем. Пока FX не согласован, отдельные валютные кошельки и итоги по валютам, без фиктивной конвертации.

## 6. Правила виртуальной торговли первой версии

1. Только акции и виртуальные деньги; никакого брокерского токена, вывода денег, настоящего пополнения или торгового API.
2. Без плеча, коротких позиций, дробных акций, деривативов и расширенных часов на старте. Доступность конкретного инструмента подтверждается capabilities.
3. Демо-рыночная покупка/продажа только во время подтверждённой обычной сессии при свежей разрешённой realtime-котировке. Closed/halted/unknown/stale → отказ с объяснением; не молчаливая сделка по вчерашнему закрытию.
4. В подробностях всегда написано: «Учебное исполнение по данным поставщика; реальная сделка могла бы исполниться иначе». Если нет bid/ask, не имитировать биржевой спред незаметно. Правило расчёта учебной цены и комиссии явно раскрывается и версионируется.
5. Сервер повторно проверяет данные, количество, размер лота, деньги и позицию. Одновременные покупки не могут сделать остаток отрицательным. Повтор с тем же ключом возвращает ту же сделку, а не создаёт вторую. Тот же ключ с другим содержимым отклоняется.
6. Виртуальный остаток, позиция, комиссия и событие ledger изменяются атомарно. В журнале хранится снимок разрешённых параметров котировки и версия правил в объёме, разрешённом договором.
7. Средняя стоимость учитывает комиссии покупки; продажа рассчитывает реализованный результат по документированному методу. Изменение стоимости позиции не становится поступлением денег.
8. Сплиты, делистинг и дивиденды нельзя игнорировать в долгоживущем портфеле. До реализации корректных corporate actions блокировать затронутый инструмент и объяснять причину, не показывать ложную прибыль. Учебный учёт не выдаётся за налоговый расчёт.
9. Не обещать точность биржевого matching engine: нет модели очереди заявок и гарантии исполнения реального объёма. Ограничения тренажёра видны в подтверждении.

Счёт инвестиций хранится отдельно от `fp_balance`, обычных транзакций, резервов, цели и `calcMetrics()`. Ни демосделка, ни сброс счёта не меняют дневной бюджет Fintex.

## 7. Учебный сценарий и интерфейс

Точка входа: отдельная карточка «Учиться инвестировать» в финансовом центре, без перегрузки нижней навигации. На каждом экране заметно «Демо · Виртуальные деньги».

### Первая версия

- Обзор учебного счёта: остатки и позиции по валютам, результат с понятной методикой.
- Каталог: поиск, биржа, валюта, режим данных, избранное; фильтр доступных рынков.
- Карточка акции: цена и её время, источник/задержка, график, простые определения терминов. Никаких выдуманных объяснений роста и обещаний доходности.
- Покупка/продажа: количество, расчёт суммы и учебной комиссии, итоговый остаток, подтверждение и явный статус.
- История и дневник: «Почему покупаю?», «На какой срок?», «Что изменит моё решение?».
- Явный сброс демосчёта с подтверждением. Стартовую виртуальную сумму/валюты согласовать перед реализацией.

### Пять стартовых уроков

1. Акция — доля в компании, не обещание дохода. Задание: найти биржу и валюту инструмента.
2. Котировка, время и сессия. Задание: отличить realtime от delayed и stale.
3. Стоимость сделки и комиссии. Задание: рассчитать доступное количество перед демопокупкой.
4. Концентрация и диверсификация. Задание: определить долю крупнейшей позиции; объяснить, что несколько акций одного сектора не устраняют риск.
5. Результат и горизонт. Задание: различить реализованный/нереализованный результат и пересмотреть запись дневника.

За знания и выполнение заданий — прогресс. Не награждать за количество сделок, плечо, самый высокий доход или покупку определённой компании. Без рейтинга «кто больше заработал» и без персонализированных торговых сигналов.

## 8. Этапы и критерии готовности

### A. Архив первоначального плана согласования источника

- Актуальное ограничение: бюджет на подписку данных равен нулю; платные кандидаты не подключать.
- Получить письменное подтверждение учебного использования, списка рынков и доставки данных браузеру.
- Определить страны пользователей, валюты и масштаб пилота.
- Отдельно согласовать расходы/хостинг. Не покупать подписку автоматически.

### B. Изолированное ядро и тестовый стенд (частично реализовано: обучение, дневник и фиксированный виртуальный остаток; без торгового ledger)

- Модель инструментов, decimal ledger, идемпотентность и изоляция от обычных финансов.
- Явно маркированные фикстуры только в тестах/стенде. В пользовательском разделе нельзя показывать тестовые цены как рыночные.
- Интерфейс без источника показывает «Котировки ещё не подключены» и блокирует сделки.

### C. Подключение лицензированных данных

- Ключ через секреты окружения, адаптер, проверка ответа и исходных времён, кэш, квоты и защита API.
- Проверка небольшого списка бумаг по каждой подключённой бирже: валюта, точность, часовой пояс, режим данных, корпоративные события и доступность.
- Не подключать весь каталог в постоянный поток: подписки только на активные карточки и выбранные позиции в пределах общей квоты.

### D. Учебные сделки и уроки

- Buy/sell + подтверждение + история, только в допустимом режиме данных.
- Подтверждённые правила комиссии, округления и учёта результата.
- Проверки двух тем, 320/390/448 px, клавиатуры, reduced motion, Telegram и обычного браузера.

### Обязательные негативные тесты

- Повторная отправка/двойное нажатие, параллельные покупки, повтор после сетевого таймаута.
- Недостаток денег, продажа лишнего количества, нулевое/отрицательное/NaN/слишком большое количество, неверный лот.
- Подмена цены/валюты/id инструмента клиентом, чужой account id, просроченная сессия.
- Старые/будущие timestamps, отсутствие торгового статуса, закрытая биржа, остановка торгов, rate limit и отказ поставщика.
- Сплит/делистинг, одинаковые тикеры на разных биржах, разные валюты и единицы котировки.
- Сброс счёта при активном запросе, восстановление после перезагрузки, сохранность обычного бюджета.

## 9. Следующие шаги без платных сервисов

1. Улучшать обучение и практические задачи без выдачи условных чисел за рыночные котировки.
2. Проверять только бесплатные источники с правами на публичный показ, учебное исполнение и хранение. Ограниченный рынок и явно обозначенная задержка допустимы; формулировка «все акции realtime» — нет.
3. При отсутствии подходящего источника сохранять доступность уроков и дневника, а сделки — заблокированными. Не подключать платный тариф как обходное решение.
4. Если бесплатный источник подтвердится, отдельно проверить инфраструктуру, правила исполнения и негативные сценарии из раздела 8 до активации демосделок.

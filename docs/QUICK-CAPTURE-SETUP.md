# Quick Capture v1 — подготовка запуска

## Что уже сделано, а что ещё нет

Готовы: настройка в FINTEX; отдельные append-only ключи; отзыв/замена; API разбора OCR-текста с обязательным подтверждением; структурированное сохранение в существующий revisioned ledger; защита от повторов по SHA-256 исходного файла. Доступ к Google Apps Script и к Apple «Командам» из этой среды отсутствует. **Развёртывание сервера, создание/проверка настоящей команды на iPhone и публикация iCloud-ссылки должны быть выполнены владельцем.** Не подставляйте выдуманную ссылку и не называйте JSON или неподписанный workflow готовой устанавливаемой командой.

## 1. Обновить существующий сервер

1. Откройте существующий проект Google Apps Script. Замените код готовым `downloads/Fintex-Code.txt` (то же содержимое в `.gs`). Альтернатива — три файла `backend/Auth.gs`, `backend/Code.gs`, `backend/QuickCapture.gs`. Не оставляйте старые дублирующие определения функций.
2. Сохраните прежние Script Properties: `FINTEX_SS_ID`, `FINTEX_BOT_TOKEN`, `FINTEX_AUTH_SECRET`. **Не запускайте создание новой базы. Не переключайте исходную защищённую таблицу.**
3. Обновите версию существующего web-app deployment (выполнение от владельца; доступность endpoint для запросов «Команд», авторизация реализуется внутри API). Существующий `/exec` остаётся прежним.
4. Через Telegram откройте FINTEX → Настройки → Quick Capture → Проверить подключение. Не отправляйте Telegram initData, bot token или auth secret в «Команды».

Ключ команды отдельный от старого СМС webhook. Сервер хранит только HMAC ключа в Script Property `FINTEX_QC_<verified uid>`. Замена/отзыв не затрагивают старую автоматизацию. Поддерживается один активный ключ Quick Capture на аккаунт: новая привязка отключает прежнюю, в том числе на другом iPhone. Для большого числа пользователей вместо Script Properties потребуется масштабируемое хранилище и дополнительные ограничения по источникам/запросам; это не массовый production gateway. На один активный ключ действует лимит 300 разборов/новых сохранений в день по часовому поясу сервера; повтор уже сохранённого запроса не расходует лимит.

## 2. Создать и проверить команду на iPhone

Название: **Добавить в FINTEX**. В параметрах включите «На странице экспорта» / Show in Share Sheet, типы входа — изображения и файлы изображений. Названия действий зависят от языка и версии iOS; это спецификация сборки владельцем, не утверждение о проверке на физическом устройстве.

Логика команды:

1. Примите ровно один файл. При отсутствии или нескольких изображениях покажите подсказку и завершите команду, ничего не отправляя. Не снимайте новый скриншот автоматически.
2. В действии «Текст» создайте **личную настройку JSON**, запросив её при импорте команды. Значение из FINTEX содержит `protocol`, `endpoint`, `uid`, `token`. В публичной команде это поле пустое: реальный ключ или ID пользователя не должны попадать в iCloud-шаблон. Получите словарь из JSON.
3. Проверьте `protocol == 1`, endpoint по `^https://script\.google\.com/macros/s/[A-Za-z0-9_-]+/exec$`, uid — цифры, token — 64 строчные hex-цифры. Иначе остановитесь. **Нельзя отправлять ключ по произвольному адресу**, в query string, URL установки, аналитике или уведомлении.
4. Получите SHA-256 **исходных байтов файла до преобразования картинки** (действие Hash / Generate Hash). Приведите hex к нижнему регистру; сохраните как `capture_id`. Не используйте новый UUID или текущее время: это ломает повторяемость. Способ получения файла из «Фото» может перекодировать его — это нужно проверить на целевых iOS/источниках.
5. Действие «Извлечь текст из изображения» (Apple OCR на устройстве). Сам файл серверу не отправляйте. Если текста нет/больше 4000 символов — предложите ручной ввод или открытие FINTEX. Сообщите, что извлечённый текст будет отправлен **этому серверу** для предложения полей, без хранения текста.
6. «Получить содержимое URL»: POST к endpoint, JSON-тело `quick_capture_parse` по контракту ниже. Разрешение на сеть может спросить iOS. Если `ok != true`, покажите ошибку, не показывайте успех и не отправляйте сохранение автоматически.
7. Из `candidate` возьмите предложения. Если он `null`, запросите поля вручную. Последовательно запросите/позвольте исправить: сумму (число, 2 знака после запятой), дату (ISO `yyyy-MM-dd` без времени), получателя, категорию, направление **Расход / Доход / Между своими счетами / Отмена**. Для собственных переводов или отмены остановитесь с подсказкой добавить перевод в приложении. Не выводите успех. Не отправляйте нулевые/отрицательные суммы и другие валюты.
8. Сопоставьте категории: Продукты→`food`, Транспорт→`taxi`, Кафе→`cafe`, Развлечения→`fun`, Подписки→`subs`, Покупки→`shop`, Здоровье→`health`, Прочее→`other`. Доход: `type=income`, расход: `type=expense`.
9. Покажите итог **со всеми полями** и меню **Сохранить / Отмена**. Отмена завершает команду. Только после «Сохранить» установите `confirmed=true`.
10. POST `quick_capture_submit` с тем же capture_id и подтверждёнными полями. Не отправляйте сюда полный OCR, изображение, остаток, bank token или initData.
11. Проверьте JSON: `ok == true`, `quick_capture_protocol == 1`, `status == saved` или `duplicate`. Только тогда покажите «Сохранено в облаке FINTEX» / «Уже получено ранее — проверьте историю». Иначе покажите ошибку. При сетевой ошибке статус неизвестен; предложите повторить исходный запрос, не создавая новый capture_id. Перезапуск с тем же файлом/полями безопасен. Это **не** обещание фоновой очереди без сети.

Нужно различать этапы 6 и 10: `saved:false` у разбора **не означает сохранение**. Нет финального подтверждения — нет POST submit. Не заменяйте это универсальным Get URL без проверки ответа.

## 3. Проверить на устройстве и опубликовать шаблон

- Проверить: расход и доход с копейками; два числа (комиссия/остаток); отсутствие даты; отмена; иностранная валюта; свой перевод; повтор одного исходного файла; потеря сети до/после POST; отозванный ключ; появление одной операции и верного остатка после синхронизации в FINTEX.
- Перед публикацией **удалить личную настройку, ключи, ID и скриншоты**. Добавить import question для JSON-настройки.
- В Apple «Команды» создать iCloud-ссылку общего доступа к проверенному шаблону. Нужен реальный результат Apple вида `https://www.icloud.com/shortcuts/<32 hex>`; его нельзя сгенерировать произвольным ID.
- В Script Properties установить `FINTEX_QC_SHORTCUT_URL` в этот URL. FINTEX получает его после явной проверки сервера и только тогда показывает кнопку установки. Другие хосты/query/fragment не принимаются.
- Проверить установку с чистого iPhone, настройку через импорт и успешный захват. Не публиковать ссылку до этой проверки.

## HTTP-контракт v1

Все вызовы — POST JSON (в браузере `Content-Type: text/plain;charset=utf-8`, из Shortcuts допустим `application/json`). Ключи только в теле запроса, TLS обязателен. Ответы GAS содержат `ok/code/error`; проверяйте JSON, не только HTTP 200.

Настройка (`quick_capture_status`, `quick_capture_pair`, `quick_capture_revoke`) — **только** через действующий Telegram initData, не токен команды. `pair` возвращает ключ один раз; `status` никогда не возвращает ключ.

Разбор (может ошибаться, не меняет финансы):

```json
{"action":"quick_capture_parse","uid":"<из личной настройки>","token":"<из личной настройки>","text":"Покупка 100,25 RUB Кофе"}
```

Возвращает `candidate` (или `null`), `warnings`, `requires_confirmation:true`, `saved:false`. Дата без явного значения может быть предложена как сегодня — пользователь обязан её проверить. Разбор не использует внешние AI/OCR API и не пишет raw-текст в Sheets/Logs.

Сохранение:

```json
{
  "action":"quick_capture_submit",
  "uid":"<из личной настройки>",
  "token":"<из личной настройки>",
  "capture_id":"<SHA-256 исходного изображения, 64 строчные hex-цифры>",
  "confirmed":true,
  "transaction":{"date":"2026-11-24","amount":100.25,"merchant":"Кофе","category":"cafe","type":"expense","currency":"RUB"}
}
```

Ответ успеха: `{"ok":true,"quick_capture_protocol":1,"status":"saved","transaction_id":"qc_…"}`. Повтор: `status:"duplicate"`. Нет суммы баланса/истории в ответе ingest-токену. Тот же capture_id с другими полями → `QC_ID_REUSED`; редактировать надо существующую запись через FINTEX. Удалённая/изменённая операция при повторе не воскрешается и не переписывается.

Защитная граница: один LedgerEvents append содержит операцию, финансовую дельту и idempotency ID под script lock. Нет отдельной записи баланса после append, из-за которой потерянный ответ мог бы повторно списать деньги. Существующие `ledger_sync` и `init` видят операцию в том же аккаунте. Другой файл или операция, ранее добавленная вручную, не дедуплицируются по совпадению суммы автоматически.

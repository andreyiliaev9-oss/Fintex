# Пароль и код сброса в Telegram — подключение Fintex v35

**Код готов в репозитории, но ваш Google Apps Script ещё нужно обновить вручную.** Публикация сайта сама по себе не устанавливает сервер и не включает отправку сообщений. У агента нет доступа к редактору вашего Google Apps Script, токену бота и таблице.

Платные сервисы и подписки не нужны. Используются текущий бот, Google Apps Script и Google Sheets; действуют их бесплатные квоты. При превышении квот сервер может временно не отвечать — это не обходит пароль.

## Что получает пользователь

- Первый запуск **в Telegram**: создание пароля из 10–128 символов с повтором. Пароль может содержать пробелы и кириллицу; вставка и менеджеры паролей разрешены.
- Следующий запуск: экран «С возвращением», ввод пароля и кнопка показа/скрытия.
- «Забыли пароль?» → явная отправка кода в личный чат **того же бота**, которому принадлежит Mini App → 6 цифр → новый пароль.
- Настройки → «Пароль и доступ»: смена с текущим паролем, выход со всех устройств, обновление ключа iOS-автоматизации.
- Перезагрузка, уход в фон, 5 минут без действий или истечение 30-минутного сеанса требуют нового входа. При восстановлении доступа переключение в чат за кодом не сбрасывает форму.
- При отсутствии связи или старом API экран не открывается «в обход» пароля.
- «Лес» и «Сапфир», светлый/тёмный режим, клавиатура, вставка одноразового кода и ширина 320 px поддержаны.

## 1. Сохраните резервную копию

Скопируйте существующий проект Apps Script и финансовую таблицу. Сохраните локальные данные браузера доступным вам способом. Не удаляйте листы `Users`, `Transactions`, `Logs`: новая версия использует их прежние колонки и добавляет лист `Auth`.

Этот сервер не является полным двусторонним журналом: удаление локальной операции не удаляет её из облака, а синхронизация не разрешает все конфликты нескольких устройств. Эти существующие ограничения не следует принимать за защиту паролем или полноценное резервное копирование.

## 2. Замените серверные исходники

В **существующем** проекте на script.google.com:

1. Замените прежний `Code.gs` содержимым `backend/Code.gs`.
2. Создайте файл `Auth.gs`, скопируйте `backend/Auth.gs`.
3. Создайте файл `PasswordKdf.gs`, скопируйте **весь** `backend/PasswordKdf.gs`.

Не оставляйте рядом старые дубли `doPost` / `doGet`. Все три файла необходимы. `PasswordKdf.gs` — готовая автономная сборка MIT-библиотеки `@noble/hashes` 1.8.0; браузерные CDN и Node.js на сервере не нужны. Лицензия — `backend/noble-hashes-LICENSE.txt`.

Для разработчика воспроизводимая пересборка:

```sh
npm ci
npm run build:auth
```

`getDb()` больше не создаёт новую пустую таблицу при ошибке доступа к старой. Существующие заголовки проверяются перед работой; при несовпадении исправьте конфигурацию, не удаляйте данные.

## 3. Задайте свойства скрипта — не в исходниках и не в чате

Откройте **Настройки проекта → Свойства скрипта**:

| Свойство | Значение |
| --- | --- |
| `FINTEX_BOT_TOKEN` | Токен **того бота, из которого запускается Mini App**. Храните только на сервере. |
| `FINTEX_AUTH_SECRET` | Постоянный случайный секрет: ровно 64 шестнадцатеричных символа (32 криптографически случайных байта). |
| `FINTEX_SS_ID` | ID вашей **существующей** таблицы из её адреса. |

Для генерации секрета выполните **на собственном компьютере** с Node.js:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Скопируйте результат напрямую в свойства Apps Script. Не присылайте его в переписку и не коммитьте. Не используйте пример, UID, токен бота или выдуманную фразу вместо случайного секрета. Сохраните секрет в надёжном хранилище администратора и не меняйте при каждом развёртывании: смена аннулирует сеансы и существующие проверочные значения паролей, после чего пользователям понадобится сброс через Telegram.

Часовой пояс проекта должен соответствовать тому, как вы датируете банковские операции. Автоматически менять его при обновлении не нужно.

## 4. Разрешения и развёртывание

1. В редакторе вручную запустите `setupFintexBackend` от имени владельца. Дайте необходимые разрешения для таблицы и внешних запросов. Функция проверит бота через `getMe`, не отправляя пароль или код.
2. **Развернуть → Управление развёртываниями → текущее развёртывание → Изменить → Новая версия.** Выполнение — от имени владельца. Доступ — «Все», чтобы POST из Mini App мог дойти до скрипта; доступ к данным проверяет код сервера, а не доверенный `user_id` из запроса.
3. По возможности сохраните тот же `/exec`, который вы прислали. В `auth.js` он уже указан адресом по умолчанию. Если адрес другой, укажите его в «Подключение к серверу» на экране ошибки входа; кастомный ранее сохранённый адрес не перезаписывается молча.
4. **Отключите все старые публичные развёртывания со старым API, имеющие доступ к той же таблице.** В том числе старые `/exec` и копии проектов: иначе через них останется доступ без пароля, независимо от защиты новой версии.
5. Только после подготовки сервера публикуйте обновлённые файлы сайта. Старый клиент не имеет password-session, поэтому после обновления сервера его облачная синхронизация перестанет проходить до обновления клиента.
6. Укажите сайт Mini App у того же бота. Откройте **личный** чат с ботом и нажмите **«Начать» / `/start`**. Бот не может отправить сообщение пользователю, который его не запускал или заблокировал.

Если проект раньше использовал привязанную таблицу без `FINTEX_SS_ID`, всё равно явно укажите ID. Не создавайте новую базу вместо существующей. Не делайте таблицу публичной и не публикуйте листы с паролями.

## 5. Проверка после публикации

На тестовой учётной записи, затем на своей:

1. Откройте Mini App именно в Telegram. Должен появиться экран создания пароля.
2. Создайте пароль. Откроется приложение, данные не должны исчезнуть.
3. Закройте/откройте приложение: требуется пароль. Неверный пароль не открывает баланс.
4. Нажмите «Забыли пароль?» и **«Получить код в Telegram»**. Убедитесь, что сообщение пришло в личный чат нужного бота.
5. Введите код и новый пароль; старый пароль и старые сеансы должны перестать работать.
6. Проверьте смену пароля в настройках и выход со всех устройств.
7. Обновите ссылку iOS-команды: первоначальное включение и сброс пароля создают новый ключ автоматизации. Можно сделать это отдельно кнопкой «Обновить ключ автоматизации iOS». Обычная смена пароля ключ автоматизации не меняет.
8. Убедитесь, что запрос старого API только с UID или старым ключом больше не возвращает финансовые данные.

**Реальная доставка кода не проверена агентом:** требуется ваш бот, ваши свойства скрипта и фактическое развёртывание. Превью интерфейса использует имитацию ответа API, не настоящий сеанс Telegram.

## Что именно защищено

- Telegram `initData` проверяется сервером по HMAC-SHA256 с токеном бота. Проверяются подпись, уникальность полей, UID, дата (до часа, допустимый уход часов вперёд — минута). `initDataUnsafe`, введённый UID и гостевой ID не считаются доказательством личности. Если данные запуска устарели, Mini App нужно закрыть и открыть заново.
- В `Auth` хранится соль и серверный ключевой проверочный хэш: PBKDF2-HMAC-SHA256, **600 000 итераций**, 32 байта, затем HMAC с отдельным секретом и UID. Пароль не хранится открытым текстом. Обработка пароля может занимать несколько секунд и потребляет квоты Apps Script.
- 5 неверных попыток пароля дают блокировку на 15 минут. Блокировка и счётчики сохраняются на сервере, перезагрузка страницы их не обходит.
- Сеанс подписан HMAC, привязан к UID и версии пароля, ограничен 30 минутами. В браузере он находится только в памяти, не в localStorage, sessionStorage или URL.
- Смена/сброс пароля и явный выход увеличивают серверную версию, аннулируя прежние сеансы. В других вкладках этого браузера отправляется сигнал блокировки; другие устройства узнают о выходе при следующем запросе или завершении срока сеанса. Если сервер недоступен во время выхода, локальный сеанс удаляется, удалённые — завершаются по сроку действия.
- Код сброса: 6 цифр, 10 минут, максимум 5 попыток, повторная отправка не чаще минуты и не больше 3 за час. Сохраняется только HMAC кода с привязкой к UID; код отправляется только на подтверждённый Telegram UID. При неудачной доставке активный код удаляется. Новый код заменяет предыдущий.
- Запросы изменения пароля и сброса требуют соответственно действующий сеанс с текущим паролем либо проверенный Telegram и код из личного чата.
- `init`, `push_tx`, `set_config` требуют password-session. Ключ из iOS Shortcut **не позволяет читать данные, менять пароль или настройки** — только добавлять распознанные операции. Он остаётся секретом, его нельзя публиковать. GET-ссылка iOS содержит этот ключ и банковский текст; берегите историю и саму команду, предпочтительнее POST.
- Ключи и коды выводятся из HMAC с криптографически случайным серверным секретом и уникальными значениями; `Math.random()` для серверных токенов не используется.
- `ScriptLock` защищает проверку/запись дублей, счётчиков и версии. Это не полноценная транзакционная БД: принудительно оборванное выполнение или сбой Sheets может оставить частично записанные данные. Полного автоматического rollback нет.
- Логи не сохраняют пароли, initData, коды, токены и полный текст банковского уведомления. Старые строки логов автоматически не очищаются; проверьте, нет ли в них ранее сохранённых секретов. Фактические суммы и история остаются в финансовой таблице.

## Чего пароль не делает

**Это защита входа и нового облачного API, не шифрование устройства.** Финансовые записи по-прежнему лежат в localStorage/IndexedDB в существующем виде. Человек с доступом к инструментам разработчика, файлам браузера, вредоносному расширению или выполнению кода на вашем домене может прочитать их или изменить клиентский экран. Это не банковская сертификация и не полный аудит всего приложения на XSS.

Обычный браузер без Telegram остаётся отдельным **локальным режимом без облачной авторизации**. После включения защиты в этом профиле без Telegram экран заблокирован; сброс локального хранилища не аннулирует серверный пароль, но удаляет клиентские данные. Не предлагайте очистку хранилища как «сброс пароля».

После первого успешного входа профиль помечается подтверждённым UID. Если в нём открыта другая учётная запись Telegram, приложение не показывает и не загружает её поверх прежних локальных записей: нужен отдельный профиль браузера либо возврат к исходной учётной записи. Это предохранитель от смешивания данных, не криптографическая изоляция локального диска.

Пароль Mini App не защищает сам Telegram от захвата. Используйте код-пароль и двухэтапную проверку Telegram. Доступ владельца к Google-таблице, скрипту и свойствам остаётся административным; ограничьте редакторов. Пока существует старое незащищённое развёртывание или публичная копия таблицы, защита нового API недостаточна.

## Адрес нового развёртывания

После настройки владелец предоставил новый адрес веб-приложения:

```text
https://script.google.com/macros/s/AKfycbyzfhzExalPbmThOsQ24Sq3-qOq_7aLSPQ69dShDbRawnawVIyR5L3hLlN1PSkCHFIM/exec
```

Он указан по умолчанию. Четыре известных прежних адреса Fintex автоматически заменяются им в настройке подключения; произвольные пользовательские адреса сохраняются. Ссылка `/macros/library/…` — библиотека, её не нужно вставлять в приложение. Это обновление адреса не подтверждает доставку кода или работоспособность настоящего сервера: проверка выполняется входом в Mini App. Старые публичные развёртывания с доступом к той же таблице необходимо отключить вручную.

## Если прежняя таблица пуста или её структура не подходит

Только по явному решению владельца можно запустить в редакторе `createFintexDatabase` (функция находится в актуальном `backend/Code.gs`; для уже установленного старого кода есть отдельный фрагмент `downloads/Create-Fintex-Database.txt`, который добавляется в конец файла).

Функция создаёт приватную таблицу `FINTEX_Database` с правильными заголовками Users/Transactions/Logs/Auth, сохраняет старый ID в `FINTEX_PREVIOUS_SS_ID` и переключает `FINTEX_SS_ID`. Старая таблица не удаляется и не редактируется. Если выполнить функцию повторно, уже созданная база не заменяется. Если первоначальное заполнение заголовков завершилось ошибкой, подключение к прежней базе сохраняется (незавершённая новая таблица может остаться на Диске).

Это **новая пустая облачная база**, а не перенос истории: старые облачные записи, пароли и ключи iOS из другой таблицы в неё не копируются. Бот и служебный секрет в свойствах скрипта сохраняются. Локальные данные приложения функция не читает и не очищает.

Создание выполняется только вручную владельцем в редакторе, не через публичный API. Редактирование `FINTEX_SS_ID` действует и для текущего развёртывания, поэтому при добавлении только этой функции новую `/exec`-ссылку получать не нужно.

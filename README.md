# FINTEX — личные финансы

Статическое приложение для браузера и Telegram WebApp. Финансовые данные пользователя остаются в существующих localStorage / IndexedDB; подключение к настроенному облачному API не менялось.

## Обновление интерфейса v4.2

Единый визуальный стиль **Living Forest**: насыщенные лесные поверхности, лиственно-зелёные и тёплые золотые акценты, согласованные карточки, элементы управления, нижняя навигация и модальные окна. Поддерживаются тёмная и светлая темы. Главная карточка заново свёрстана с отдельным блоком дневного бюджета; идентификаторы финансового рендера сохранены.

- `design-system.css` — общие токены цвета, радиусов и теней, компоненты и адаптеры для динамических модулей (аналитика, дерево, симулятор, Stories, заставка).
- `styles.css` — существующая базовая вёрстка и анимации; конфликтующие градиентные поверхности и фоновые блики удалены.
- `assets/utilities.css` — собранные Tailwind-утилиты, без CDN-компиляции в браузере.
- `assets/icons.js` — локальная, зафиксированная версия Lucide; лицензия рядом.
- `ui/tailwind.css`, `tailwind.config.cjs` — исходник и конфигурация сборки утилит.

Цвета и общие размеры компонентов меняются через токены в `design-system.css`. Цвета категорий, предупреждений и доходов имеют самостоятельный смысл и не должны заменяться одним брендовым цветом.

## Запуск

Для обычного просмотра Node.js не нужен:

```sh
python3 -m http.server 3000 --bind 0.0.0.0
```

Открыть `http://localhost:3000`. Для GitHub Pages достаточно опубликовать статические файлы **вместе с папкой `assets`**. Готовые UI-ресурсы сохранены в репозитории; установка npm-зависимостей на хостинге не требуется.

После изменения классов в HTML или JS пересобрать утилиты:

```sh
npm ci
npm run build
```

Telegram SDK и движки QR / OCR / PDF пока загружаются с прежних внешних адресов; локализация UI-ресурсов не означает полноценного офлайн-режима всего приложения.

## Проверки

```sh
npm test
npx playwright install chromium
npm run test:ui
```

Для уже установленного Chromium можно указать `CHROMIUM_EXECUTABLE_PATH`.

Браузерные тесты проверяют четыре вкладки на ширинах 320 / 390 / 448 px в обеих темах, совпадение поверхностей динамических модулей, открытие окон, скрытие сумм, периоды аналитики, Stories и первый вход. В тестах внешние запросы заблокированы: проверяется независимость интерфейса от CDN, но не распознавание чеков, облачная синхронизация или работа внутри реального Telegram.

Дополнительно исправлен вызов симулятора из аналитики: используется существующий `SIM.ui.openModal()` с сохранением контекста объекта.

### Календарь и появление операций v24

- Расходы — коралловые, доходы — зелёные, запланированные платежи и зарплата — золотые. Выбранный день не перекрашивает суммы в цвет бренда.
- На смешанных днях видны и расходы, и доходы; пустые дни больше не отмечаются зелёными точками.
- Фильтры управляют и сеткой, и списком выбранного дня. Вкладка «Платежи» не показывает обычные операции.
- Операции выбранного дня расположены сразу под календарём; дополнительный план до зарплаты свёрнут отдельно.
- Строки операций в календаре и на главной проявляются с небольшим подъёмом и задержкой 65 мс. За пределами экрана ждут прокрутки. При синхронизации анимируются только новые строки, а не вся история. Отключение анимаций и `prefers-reduced-motion` учитываются, в том числе во время воспроизведения.
- При смене месяца выбранная дата переносится в новый месяц с ограничением последним днём (31 января → 28 февраля).

`docs/calendar-preview.png` — снимок календаря на тестовых данных. Браузерные сценарии дополнены проверками цветов, фильтров, смешанного дня, границ месяцев и поведения анимаций.

### Заставка «Росток» v25

Вместо космической сцены — локальный SVG-росток: прорисовка стебля, раскрытие двух листьев, название Fintex и «Расти в своём темпе». Полная сцена длится 5 секунд (4,6 с до начала выхода + 0,4 с затухания). Без баланса, банковских данных, фиктивных этапов загрузки, canvas и сетевых ресурсов.

- Касание, кнопка «Пропустить» или Escape закрывают заставку раньше.
- При `prefers-reduced-motion` или отключённых анимациях вход происходит без заставки и ожидания. Изменение настройки во время показа немедленно закрывает сцену.
- Пока заставка открыта, фон недоступен для клавиатуры и прокрутки; после выхода восстанавливаются фокус и взаимодействие.
- Повторный запуск доступен в настройках: «Посмотреть заставку „Росток“». Старые таймеры отменяются при повторном запуске и уходе приложения в фон.
- Первый вход по-прежнему открывает onboarding, не заставку возвращающегося пользователя.

`docs/sprout-preview.png` — финальный кадр тёмной версии. Историческое имя `cosmic_intro.js` сохранено для совместимости, содержимое полностью заменено. Контроллер загружается перед `app.js`, чтобы при запуске не возникала старая заставка.

### Бесплатные учебные инвестиции v26

В аналитике и настройках появилась карточка **«Учиться инвестировать»**. Это первая, полностью бесплатная учебная основа — **не работающая биржа и не подключённый брокерский счёт**.

- Отдельный виртуальный остаток 100 000 ₽; личный баланс, лимиты, расходы и цели не затрагиваются.
- 5 уроков с вопросами, объяснениями и сохранением пройденного. Прогресс за знания, не за частоту сделок или доходность.
- Дневник: компания/тикер, причина, горизонт, риски и условия пересмотра. Это текстовые заметки, не заявки.
- Котировки и каталог ещё не подключены, покупка и продажа заблокированы. Нет фиктивных графиков и случайных цен под видом рынка.
- **Платные источники котировок не используются и не планируются.** Бесплатность API не заменяет проверку прав на показ данных пользователям.
- Хранение локальное в `fp_invest_learning_v1`; облачной синхронизации нет. Очистка браузера может удалить записи. Сброс с подтверждением затрагивает только обучение.
- Ошибки чтения не приводят к молчаливой перезаписи, ошибки сохранения показаны в интерфейсе. Введённый текст экранируется.

`investments.js` — автономный модуль без сетевых вызовов и ключей API. `tests/investments.test.cjs` — схема и изоляция хранилища; браузерные проверки покрывают уроки, дневник, сброс, ошибки, темы и мобильные ширины. `docs/investments-preview.png` — снимок учебного счёта. План и архив исследования: `docs/investments-plan.md`.

### Второй природный стиль «Лагуна» v29 (история; заменён «Сапфиром» в v31)

**Настройки → Внешний вид → Стиль:** «Лес» (по умолчанию) или «Лагуна». Стиль не связан с режимом: оба доступны в светлом, тёмном и автоматическом вариантах. Лагуна сочетает глубокий сине-зелёный фон, мягкую бирюзу, песочные акценты и тонкие линии воды. Дерево сохраняет натуральную зелень, доходы — зелёный, расходы — коралловый, плановые платежи — золотой.

- `appearance.js` применяет сохранённый выбор в `<head>`; `fp_visual_style` хранится отдельно от существующего `fp_theme`. Старый выбор режима сохраняется; финансовые данные не мигрируют и не изменяются.
- Автоматический режим следует оформлению Telegram внутри Telegram, а в обычном браузере — `prefers-color-scheme`; реагирует на изменения без перезагрузки. Явный светлый/тёмный режим не переопределяется устройством.
- Обновляются цвет браузерной панели и запрашиваемые цвета заголовка/фона Telegram. Выбор синхронизируется между вкладками; неизвестные значения безопасно возвращают «Лес»/тёмный режим. При ошибке сохранения показано сообщение.
- Карточки стилей доступны с клавиатуры и имеют `aria-pressed`. Актуальная палитра и превью — в разделе v31 ниже.

Проверки: сборка, 14 модульных и 37 браузерных тестов. Добавлены проверки независимого выбора, сохранения после перезагрузки, устройства/Telegram (через mock SDK), синхронизации вкладок, финансовых цветов и всех вкладок на 320px. Реальное устройство Telegram и OCR/облако в этой задаче не проверялись.

### Цена в часах жизни и зелёный + абрикосовый v30

Добавлен бесплатный локальный расчёт **стоимость покупки ÷ доход на руки за месяц × рабочие часы в месяц**. Например: 3 000 ₽ при 80 000 ₽ и 160 ч = 6 ч работы. Доход не угадывается по поступлениям, рабочий график не подставляется автоматически: пользователь задаёт оба значения за одинаковый период. При нерегулярном доходе интерфейс предлагает взять средние значения.

- **Аналитика → Инструменты → Цена в часах жизни** — самостоятельный калькулятор.
- **Проверить покупку** — время по сохранённым параметрам обновляется при вводе цены; кнопка открывает полный расчёт с этой ценой.
- **Настройки → Цена в часах жизни** — настройка дохода и рабочего времени.
- Часы и минуты округлены до минуты, маленькая положительная стоимость показывается как «Меньше 1 мин». Это рабочее время, **не срок накопления**; бытовые расходы, дорога и отдых в формулу не входят.
- Доход и часы сохраняются только явной кнопкой в `fp_work_time_v1`; цена не сохраняется. Черновик не подменяет сохранённые значения. Баланс, операции, инвестиции, облако и очередь синхронизации не изменяются. Ошибки хранилища показаны; повреждённая запись не заменяется до явного сохранения новых параметров.
- `life-cost.js` содержит чистый расчёт и контроллер native dialog: Escape, возврат фокуса, удержание Tab внутри, доступные подписи и живой результат. Диалог прокручивается на коротких экранах.
- К «Лесу» добавлен **мягкий абрикосовый**: знак F, значок счёта и детали карточки расчёта. Основной зелёный сохранён. У нового акцента отдельные токены `--companion*`: красный расходов, зелёный доходов и золотой плановых платежей не заменены. В v31 для нового «Сапфира» этот акцент синий/голубой.

Превью: `docs/forest-apricot-preview.png`, `docs/life-cost-preview.png`. Проверки включают формулу, округление, запятую/пробелы, неверные/нулевые значения, пределы, изоляцию и ошибки хранения, сохранение после перезагрузки, проверку покупки и 320×568 в двух стилях и режимах. Реальное Telegram-устройство, экранная клавиатура телефона, облако и OCR не проверялись.


### Палитра по референсу — «Сапфир» v31

Второй стиль **заменён**, а не добавлен третьим: теперь в настройках «Лес» и «Сапфир». Основной зелёный «Лес» с абрикосовыми деталями не изменён. Из четырёх полос пользовательского изображения взяты наиболее частые цвета внутри каждой полосы JPEG:

| Цвет | HEX | Применение |
| --- | --- | --- |
| Молочный белый | `#F6F6F6` | Светлый фон, светлый текст на синем |
| Светло-голубой | `#D7E3EF` | Мягкие поверхности, дневной бюджет в тёмном режиме |
| Насыщенный синий | `#1F57A1` | Кнопки, активная навигация, знак F |
| Глубокий синий | `#153073` | Текст и дневной бюджет в светлом режиме, тёмный фон |

Производные синие оттенки используются для границ и тёмных поверхностей. Бирюзовые/песочные декоративные элементы прежней «Лагуны» заменены синими, графика волн — геометрическими полосами. Зелень дерева и ростка остаётся натуральной; семантические доходы/расходы/плановые платежи не перекрашены. Карточка цены в часах жизни также использует синюю палитру.

Сохранённый `fp_visual_style=lagoon` читается как `sapphire` без сброса `fp_theme` и финансовых данных; при явном выборе сохраняется новый идентификатор. Старый программный вызов `setVisualStyle('lagoon')` совместим и выбирает «Сапфир». Настройки, auto, обновления Telegram и синхронизация вкладок продолжают работать независимо от режима.

Актуальные снимки: `docs/sapphire-light-preview.png`, `docs/sapphire-dark-preview.png`, `docs/sapphire-settings-preview.png`. Браузерные проверки обновлены для обоих режимов; добавлены совместимость сохранённой «Лагуны», точные цвета палитры и контраст текста бюджета/активной навигации (не ниже 4,5:1). Проверки на физическом устройстве Telegram не проводились.

### Нейтральные цифры «Сапфира» v32

По выбранному варианту «Графит / молочный» суммы баланса, резерва, свободного остатка, накоплений дерева, нейтральные показатели аналитики и результат цены в часах жизни теперь отделены от синего цвета заголовков. На светлых поверхностях цифры графитовые `#30343B`, на тёмных — молочные `#F6F3ED`. У дневного бюджета инвертированная поверхность: цвет цифр выбирается по карточке, а не только по режиму. ### Живое «Моё дерево» v33

Дерево теперь **постоянно и мягко покачивается**, пока его видно на главной. Это бесконечная CSS-анимация, не одноразовое появление. | Записанные расходы / доходы за последние 30 дней | Дерево |
| --- | --- |
| Пока нет хотя бы одного дохода и одного расхода | Молодое дерево, без оценки |
| Больше 100% | Берёза |
| Больше 90%, но не больше 100% | Ель |
| Больше 70%, но не больше 90% | Клён |
| Не больше 70% | Дуб |

Сумма заработка сама по себе не определяет вид: при одинаковом соотношении он одинаков и для 10 000 ₽, и для 100 000 ₽. В «Подробнее» раскрыты правила, период, поступления и расходы; это визуальный ориентир по **записанным** операциям, не оценка благосостояния, не обещание доходности и не прогноз.

- Период — сегодня и предыдущие 29 местных календарных дней. Будущие даты, неверные/отсутствующие даты, нулевые/некорректные суммы исключены. Переводы, возвраты, снятие наличных и явно нерублёвые операции не участвуют; перемещения денег не выдаются за заработок. Возвраты пока не уменьшают расходы в этой визуализации.

Видимая плашка даты позволяет вернуть все операции. Добавление за дату и оплата плановых платежей сохранены. Это устранение дублирующего представления, не удаление финансовых записей и не автоматическое объединение похожих операций.

Свайп влево/вправо по содержимому переключает соседние разделы в порядке Главная → Календарь → Аналитика → Настройки, без зацикливания. После перехода экран прокручивается к началу. Кнопки панели продолжают работать. Жест не перехватывается у графиков, форм, горизонтальных лент, модальных окон, выделенного текста и краёв системного жеста «назад»; короткие, вертикальные, неоднозначные, отменённые и мультитач-жесты игнорируются. Горизонтальный свайп не запускает обновление потягиванием вниз. Поддерживаются касания по календарной сетке без случайного выбора даты; после распознанного свайпа подавляется только возможный завершающий клик в месте отпускания.

Проверены прямой/обратный порядок, границы, физический эмулированный touch-drag, исключения интерактивных областей, переход в единый журнал/сброс даты, пустая дата и неизменность финансовых данных. Сервер, доступ, отключённые уведомления и расчёты не менялись; кэш v56.

### Свайп за пальцем и короткие анимации интерфейса — v57

Свайп больше не ждёт отпускания пальца с резкой сменой экрана: текущий раздел двигается за жестом, рядом появляется название соседнего. ### Несколько целей накоплений и больше моушена — v58

На главной появился раздел «Мои цели»: общая отложенная сумма, две карточки-превью и переход в галерею всех целей. Финансовая подушка остаётся основной целью с прежними суммой и поведением дерева. Можно создать до 12 целей вместе с основной: задать название, сумму, необязательный плановый взнос в месяц, выбрать одну из четырёх локальных иллюстраций или своё фото. Фото JPG/PNG/WebP до 8 МБ сжимается до JPEG на устройстве (сторона до 800 px), не загружается на сервер и применяется только после сохранения. Неподходящий файл и переполнение хранилища не заменяют сохранённую цель. Галерея и фото хранятся в этом браузере, не являются банковскими счетами и не синхронизируются автоматически между устройствами.

Совместимое хранение: прежний `fp_goal`/`state.goal` сохраняет основную цель, новые цели находятся в `goal.pockets`; открытие экрана ничего не мигрирует и не записывает. `FintexMath.goalSavings` суммирует резерв всех целей ровно один раз. Пополнение/возврат не меняют баланс карты, журнал операций и платежи; недоступную сумму зарезервировать нельзя. Удаление дополнительной цели требует отдельного раскрытия и явного подтверждения, её деньги возвращаются в доступные. Основную подушку удалить нельзя. Симулятор исключает все цели из ликвидных денег, но сохраняет их в капитале; подушка при этом не смешивается с отпуском/техникой.

Прогноз — сценарий по явно указанному ежемесячному взносу, а не обещание или автоматическое списание: `(сумма цели − накоплено) / взнос`, округление числа месяцев вверх, первый взнос через месяц. Даты конца месяца корректно ограничиваются последним днём целевого месяца. Без плана дата не выдумывается; доходность и инфляция не добавляются. Суммы считаются в копейках. Приватность размывает суммы, прогресс и прогноз.

Моушен: каскадное появление карточек и содержимого галереи, мягкая смена обложки/отклик кнопок, рост прогресса и акцент процента после пополнения, короткий разлёт десяти листьев при достижении цели. Также добавлены конечные появления обычных модальных окон и отклик выбранного дня/сводки календаря. Выключение движения, reduced-motion и скрытие страницы отменяют эффекты, включая листопад; бесконечных новых циклов нет. Закрытие окна возвращает фокус на действующий элемент.

Тесты проверяют совместимость старой подушки, резерв нескольких целей, копейки, прогноз/концы месяца, пополнение и возврат без ложных доходов/расходов, сохранение после перезагрузки, явное удаление, локальную обработку фото, переполнение хранилища, защиту от HTML-вставок, узкие экраны, приватность и остановку анимаций. Превью: `docs/savings-goals-preview.png`, `docs/savings-goal-detail-preview.png`. Пароли, уведомления, GAS и исходная таблица не менялись.

### Живая история операций, чёткие цифры и движение денег — v59

История на главной оформлена как дневные карточки: отдельные заголовки/итоги **по показанным записям**, контрастные суммы со знаком, различимые доходы и расходы, направленные отметки возле магазина. Запись открывается не только касанием, но и Enter/пробелом.

### Полировка ежедневных сценариев и защита от случайных действий — v60

Исправлен конфликт двух горизонтальных жестов: строка операции теперь владеет своим свайпом и не запускает переход между разделами. Любой длинный свайп (пальцем или мышью) только открывает действия; автоматическое удаление за порогом убрано. У каждой строки есть доступная кнопка ⋯, отдельная кнопка открытия записи и явно подписанные «Повторить»/«Удалить». Закрытые действия исключены из фокуса через inert. Вертикальный жест фиксируется как прокрутка, мультитач/отмена/смена раздела сбрасывают перетаскивание. Escape закрывает действия с возвратом фокуса. Прежняя отмена явного удаления сохранена.

Поиск действительно учитывает товары из `items` чека, магазин и суммы с пробелами/десятичной запятой/₽. «ё» и «е» считаются эквивалентными. Показаны число совпадений, отдельное состояние «Совпадений нет» и кнопка сброса; сброс не снимает фильтр выбранного дня/типа. Открытие поиска ставит фокус в поле. Пустой день предлагает добавить операцию с уже выбранной датой, не создавая её автоматически.

`modal-accessibility.js` добавляет прежним окнам роль/название диалога, удержание фокуса, Tab/Shift+Tab, Escape через настоящий обработчик закрытия (включая остановку голоса) и возврат к актуальному элементу истории после перерисовки. На время окна фон исключён из клавиатурного фокуса и заблокирована его прокрутка; после закрытия исходный inert восстанавливается. Нативные окна Capture/целей/калькулятора сохраняют собственный жизненный цикл. Листы ограничены 92dvh и прокручиваются внутри; кнопки закрытия минимум 44 px, поля на сенсорном устройстве 16 px, чтобы не провоцировать увеличение страницы при вводе.

Отменённый pointer-жест кнопки накопления, уход пальца и закрытие окна прекращают удержание **без** резервирования денег; скрытие страницы тоже отменяет незавершённое удержание. Обычное отпускание по-прежнему подтверждает намеренное пополнение. Ни один из этих защитных сценариев сам не меняет журнал, баланс или цель.

Проверки: реальные CDP touch-жесты на операции, длинный свайп без удаления/перехода, мышь, отмена/мультитач/вертикаль, явное удаление и отмена, клавиатурные действия, локальный поиск по чеку/копейкам, сохранение даты, именованные диалоги/фокус/голос/Escape, короткий экран и прерванное удержание. Заставка теперь собрана в одну пятисекундную сцену: падает семя, рисуется стебель, с небольшим пружинящим доведением раскрываются листья, побег один раз мягко качается. При системном reduced-motion или выключенном движении заставка не задерживает вход; изменение предпочтения останавливает её сразу. Первый запуск по-прежнему открывает знакомство с приложением. Финансовые данные в сцену не попадают и не изменяются.

Проверены фазы/конечность слоёв, точное совпадение конечной позиции логотипа с шапкой, ранний и поздний пропуск, отмена полёта/повтор, все три палитры в светлом/тёмном режиме и экраны от 320×568 до 600×360. ### Дерево реагирует на касания — v64

Картинка дерева теперь — отдельная игровая кнопка **«Потрясти дерево»**, а не скрытая ссылка на накопления. Один тап даёт короткое встряхивание и локальное осыпание, второй и третий усиливают его. **Четыре быстрых касания** (не больше 750 мс между соседними, вся серия до 1,9 с) запускают один большой эффект на 2,8 с: в Лагуне — сброс снега с веток и вьюгу, в Лесу — листопад, в персиковой теме — вихрь лепестков. Подсказка под деревом показывает оставшиеся касания; результат доступен через ненавязчивый live-status. Работают touch, мышь, Enter и Space; удержание клавиши, прокрутка и отменённый жест не заряжают серию. Накопления по-прежнему открываются явной кнопкой **«+ Пополнить»**.

Для всех пяти зимних видов добавлены локальные версии без снежных шапок (`assets/trees/winter-bare/`): во время вьюги снег действительно исчезает с веток, затем мягко восстанавливается. Основная иллюстрация не скрывается, пока версия без снега не декодирована; при ошибке загрузки остаётся исходное дерево. Отдельная оболочка встряхивания не заменяет постоянное покачивание. В большом эффекте максимум 36 локальных частиц и 56 фоновых; повторные тапы во время вьюги не продлевают её и не создают дополнительные слои. Всё движение конечно, без кадровых циклов JS, звука и финансовых действий.

Отключение motion/reduced-motion, смена темы/вида дерева, выход из раздела, уход дерева за экран, открытие модального окна, скрытие страницы и resize сразу отменяют частицы, таймеры, тряску и подмену снега. Все декоративные слои `inert`, `aria-hidden`, `pointer-events:none`, ниже навигации/диалогов; центр вьюги приглушён над цифрами. Старые асинхронные загрузки после отмены не возвращают эффект. Тесты `tests/tree-interaction.spec.cjs` покрывают настоящие тапы, клавиатуру, медленные серии, спам из 200 нажатий, все отмены, пять снежных видов, шесть палитр на 320px, ошибки/задержки изображений и неизменность финансов. Превью: `docs/tree-blizzard-preview.png`, `docs/tree-leaf-storm-preview.png`, `docs/tree-petal-storm-preview.png`.

### Живая сцена дерева — v65

Все пять доработок интерактивного дерева объединены в одной сцене:

1. **Точка касания**: частицы отрываются возле пальца, а дерево отклоняется от него; касания верхней/нижней и левой/правой части отличаются. Клавиатура использует центр кроны.
2. **Возвращение сезона**: вьюга заканчивается через 2,8 с, но ветки не покрываются снегом мгновенно. Они некоторое время почти чистые, затем снежный слой постепенно проявляется в течение 12 с; новую вьюгу можно вызвать во время восстановления. В Лесу частицы отделяются после короткой дрожи, в персиковой теме шесть бутонов раскрываются и осыпаются лепестки.
3. **Ветер от жеста**: горизонтальный жест непосредственно по дереву создаёт конечный порыв в его сторону. Участок помечен `data-no-tab-swipe`, поэтому не переключает разделы; вертикальная ось остаётся нативной прокруткой (`touch-action:pan-y`). Короткие/отменённые и многопальцевые жесты не заряжают серию тапов.
4. **Глубина**: неподвижная мягкая тень на земле, отдельный слой кроны с более гибким движением, три размера ближних/дальних частиц. Крона берётся из того же локального SVG и устанавливается только после успешного декодирования; основной рисунок остаётся резервом. Новых внешних ресурсов и кадрового JS нет.
5. **Финансовые события**: только подтверждённые пополнения подушки и отдельных целей посылают `fintex:goal-funded` с единственным признаком `completed` — без суммы/названия. После закрытия диалога у видимого дерева свет идёт от корней к кроне; пересечение суммы цели даёт короткое цветение. Начальная загрузка, импорт, правка цели, возврат из резерва, ошибка валидации или сохранения не запускают поздравления. Без увядания и наказаний за расходы. Очередь ограничена одним событием на 15 с, не прокручивает страницу, не открывает разделы и сбрасывается при уходе со страницы.

Сбросы при смене темы/вида дерева, motion/reduced-motion, скрытии/прокрутке дерева, открытии модалей и resize сохранены, включая отдельные анимации восстановления снега, цветения и корневого света. Ни прикосновения, ни жесты, ни декоративные эффекты не меняют деньги. Новые тесты `tests/tree-living-scene.spec.cjs`: координаты и направление реакции, настоящие touch-жесты через CDP с проверкой вертикального скролла/отсутствия смены вкладки, поэтапное восстановление снега, разделение кроны/ствола, бутоны/глубина, оба пути реального пополнения и отсутствие ложного поздравления. Превью цветения: `docs/tree-goal-bloom-preview.png`.

### Экскурсия по приложению — v67

Новый пользователь после первого успешного ввода имени/баланса получает десятишаговый маршрут по настоящему приложению: доступно сегодня → добавление/Capture → история → календарь → аналитика → цели → дерево → настройки. - **Свои переводы:** отдельный `transfer` с названиями разных своих счетов и подтверждением, что оба входят в общий остаток. Это запись движения внутри уже учтённых денег, не исполнение банковского перевода и не многосчётная банковская система. Нулевое влияние на общий остаток; переводы/корректировки видны нейтрально в журнале, но не раздувают доходы, расходы, календарные расходы или поведенческую статистику. Удаление/отмена используют общий знаковый эффект, включая корректировки обоих знаков.
- **Полезная аналитика:** крупнейшая категория выбранного периода; этот месяц против тех же прошедших дат предыдущего (с оговоркой короткого месяца); деньги до зарплаты после неоплаченных обязательств и целей, ориентир на день. Отсутствие записей не объявляется отсутствием трат; прогноз/среднее при отсутствии расходных данных не подменяются уверенным нулём. Цветовая оценка роста расходов убрана.
- **Единый интерфейс:** нативные диалоги, одинаковые поля и кнопки, возврат фокуса, Escape, работа на 320px/коротком экране и во всех шести палитрах. Экскурсия, контекстная помощь, Capture, дерево и цели сохранены.

**Граница облака:** текущий развёрнутый backend умеет добавлять записи, но не редактировать существующие. Поэтому исправления, удаления, свои переводы и корректировки **сохраняются на этом устройстве**, что написано в интерфейсе. Исходные очереди отправки не переписываются. `fp_ledger_offset` отделяет локальные изменения остатка от облачного баланса; `fp_local_deleted_ids` не даёт облаку вернуть удалённую запись на этом устройстве. Обычные новые доходы/расходы продолжают синхронизироваться. Новые типы не отправляются неподдерживающему их серверу. Изменений/деплоя GAS и обращений к исходной базе данных в этой версии нет. Синхронизация правок между устройствами не заявляется.

Правила вынесены в `daily-model.js` и `FintexMath.ledgerEffect/ledgerTransactions`; `daily-flow.js` отвечает за подтверждённый ввод и хранение.
